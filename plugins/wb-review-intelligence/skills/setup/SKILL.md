# Подключение WB Review Intelligence 1.3.0

Это переносимый GitHub-пакет на основе анализатора1.2.2. Приватный App автора и его облачные настройки не включены. Не создавать второй WB-плагин или отдельный навык для повторного анализа/оформления. Сначала читай `../analyze-wb-reviews/references/IN-CHAT-REPORT.md` и основной SKILL.md.

## Постоянный проект Codex Desktop/CLI, включая VPS

1. Определи реальный корень проекта. Прочитай LOCAL-PROJECT.md; проверь Python/jsonschema/referencing, права файлов и POSIX flock.
2. Выполни local_project.py --project <корень> list. Setup не вызывает init: пустой пробный run_id не нужен. Используй существующие config/registry и необязательный legacy-index.json; ничего не перезаписывай ради настройки.
3. Единственное хранилище новых исследований — wb-review-intelligence внутри проекта. Старые файлы остаются по исходным путям и могут быть представлены ссылками в истории. Не создавать дубликаты в outputs/skill-runs. Drive, Sites/R2 и App не нужны для локального сохранения; не читать пользовательскую конфигурацию хранения и не загружать туда данные без запроса.
4. Для явно выбранного сохранённого исследования используй его три файла, status и checkpoint --render. Старый формат открывай без пересборки другим навыком. Проверяй выдачу по контракту клиента; render и наличие инструментов не доказывают UI=PASS. При отсутствии сохранённых данных предложи первый товар, не запускай сбор самостоятельно ради setup.

## Облачная среда ChatGPT Work

Если постоянного пользовательского проекта нет и выбран облачный режим, применяй 04-STORAGE.md. На первом запуске согласуй собственное подключение и каталог с пользователем, затем проверь фактический аккаунт/ID и сохранённый реестр. Не выбирай чужое хранилище и не создавай новый корень по ошибке. Локальный режим не запускает эту проверку. Для выбранного сохранённого отчёта — загрузка трёх файлов, status и render, без нового WB. App — дополнительный доступ только при разрешённом сохранении в сервисе; список App не является локальной историей проекта.

## Инструкция для проекта

```text
Для отзывов Wildberries используй установленный основной плагин WB Review Intelligence из этого установленного GitHub-пакета и его актуальный analyze-wb-reviews. Методика, pipeline.py и renderer принадлежат плагину.
В постоянном проекте Codex все новые исследования сохраняй только в wb-review-intelligence/runs/<run_id>/data, HTML рядом, история в registry.jsonl/index.html. Не создавать второй комплект в outputs/skill-runs и не запускать прежний локальный навык для повторной разметки/выдачи. Старые исследования сохранить и открывать по ссылкам legacy-index.json.
Новый чат начинает с local_project.py list. Продолжение/просмотр/оформление — прежний run_id и сохранённые данные без повторного сбора. Показать отчёт прямо в ответе при поддержке клиента, иначе содержательный Markdown. Не объявлять сохранение или UI-проверки успешными без подтверждения.
В облачной среде без постоянного проекта применять отдельный Drive-протокол плагина. Не синхронизировать локальные данные в облако автоматически.
```

Проверь нужные для источников подключения по фактическим инструментам, не обещай полноту WB. Не отправляй пользователя устанавливать ещё один плагин. Смена версии пакета не переносит исследовательские файлы между компьютерами; отдельно проверь версию клиента и доступ к проекту. Сохранение/встраивание/клики являются разными фактами.
