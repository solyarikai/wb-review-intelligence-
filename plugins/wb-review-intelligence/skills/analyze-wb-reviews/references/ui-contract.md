# Контракт встроенного отчёта · 0.4.0

**Приоритет 1.2.1:** запуск и выдача — IN-CHAT-REPORT.md. Достаточно ссылки WB. В постоянном проекте Codex автоматически хранить данные и HTML по LOCAL-PROJECT.md; отчёт включать прямо в ответ. При поддержке клиента использовать встроенный интерактивный вывод, иначе содержательный текст. Ссылка на файл сама по себе не выполняет выдачу отчёта. Cloud-only маршруты ниже не меняют локальное хранение; UI=PASS требует фактической проверки.

Главный результат — внутри текущего сообщения ChatGPT. Никакого HTML-файла, статичной картинки или кнопки, которая запускает другой чат/сетевой запрос вместо локального раскрытия. Платформа может не поддерживать обязательные компоненты: в таком случае покажи полный доступный текстовый отчёт, назови реальное ограничение; не имитируй интерактивность. Дизайн закреплён в `assets/report/`; способ сборки — `pinned-renderer.md`.

| Действие | Обязательный эффект |
| --- | --- |
| Артикул ↔ группа | Одновременно меняет период, все метрики, знаменатели, все темы, цитаты, Q&A, возможности и выводы. Не переносит цитаты другой области. |
| Обзор/Темы/Вопросы/Возможности | Содержательные разделы; обзор ведёт к реальным темам; вопросы — только реальная выгрузка; возможности — наблюдение/гипотеза/действие/проверка и работающая ссылка на тему. |
| Все/Хвалят/Критикуют | Фильтр тем по `context`, совместно с поиском. `Все` включает нейтральные/смешанные темы. |
| Поиск | По всем названиям тем, всем цитатам (включая ещё скрытые), полным полям; по вопросам и ответам во вкладке Q&A. Без сети/нового сообщения. |
| Открыть тему | В заголовке до открытия видны контекст, `n/N_text` и `%`; после открытия — первые 3–5 реальных подтверждений. Под цитатой **только** дата и фактический артикул WB. |
| Показать ещё/все | Раскрыть следующую порцию до 5 / все оставшиеся доказательства **в той же карточке**. После исчерпания скрыть или заблокировать. Поиск не должен зависеть от видимости цитаты. |
| Полное поле | Показать сохранённый точный `full_field_text` без технических ID; review-ID и field скрыты в UI, сохранены в данных. |
| Переход из обзора/возможностей | Переключить на Темы, сфокусировать и раскрыть существующую тему с сохранением области. |

Все темы в отчёте, включая единичные. `n` — уникальные отзывы с парой тема/context, а не количество цитат; `N_text` — все уникальные текстовые отзывы области. Если ссылки доказательств охватывают лишь `k<n` уникальных review-ID, покажи `k/n`, причину и только имеющиеся цитаты; это не полный статус доказательств. Данные цитат передаются целиком до рендера; нельзя передавать только Top-N или первые пять.

Мобильный интерфейс: без обрезанных названий вкладок/областей, без горизонтального скролла страницы; допустим перенос вкладок, селектор или прокрутка только самих вкладок с заметным индикатором. Палитра, скругления и шрифты берутся из закреплённого report.css.

**Приёмка:** убедись на готовой конструкции (не на мокапе), что работают обе области, четыре вкладки, три фильтра, скрытая цитата в поиске, единичная и длинная тема, локальное раскрытие полного поля и всех цитат, переходы, телефонная ширина. Запиши `verified`/`not_verified`/`not_available` для UI в manifest отдельно от анализа. Ни автотест схемы, ни проверка Python не доказывают фактические клики в ChatGPT. Если механизм не проверен, не называй его проверенным.

## Программная приёмка UI · 0.4.0

Контролёр не предоставляет renderer и не выполняет клики. Передать в `pipeline.py <папка> ui --input -` результат проверки **реального хоста**, не предположение о возможности UI:

- renderer_sha256 из текущего render (проверяется контролёром против assets/report); input_sha256 из текущего status/build; available=true; mechanism — фактический механизм/ревизия; checked_at — реальное время.
- inventory для каждой области: theme_ids, quote_ids, question_ids, opportunity_ids — полные множества ID **переданных в виджет**, а не только видимых строк. Множества должны точно совпасть с REPORT_DATA; пропуск группы, редкой темы или скрытой цитаты не проходит.
- checks: areas, tabs, filters, all_themes, hidden_quote_search, question_search, singleton, pagination, full_field, local_expansion, links, mobile, quote_metadata. Для каждого объект `{ "status":"PASS", "evidence":"что фактически проверено и где" }`. Нельзя подставлять одинаковое «всё работает» без действий.
- N/A разрешён с объяснением только для отсутствующей в реальных данных единичной/длинной темы, поиска Q&A без Q&A, переходов без тем. Для остальных проверок нужен PASS. Не создавать синтетические отзывы ради проверки реального отчёта.

При unavailable передать `{ "input_sha256":"<текущий hash>", "available":false, "reason":"<фактическое ограничение>" }`. UI=BLOCKED не препятствует обработке/проверке корпуса и честному текстовому результату, но запрещает общий success=true.

Receipt — проверяемая запись утверждения исполнителя, не независимое доказательство истинности кликов. JSON Schema, Python fixtures и статичный screenshot не удостоверяют интерактивность. Изменение данных автоматически делает receipt устаревшим; изменение renderer требует новой фактической проверки и нового receipt. Контролёр не может обнаружить внешнее изменение renderer без передачи нового результата; явно фиксировать mechanism/ревизию.
