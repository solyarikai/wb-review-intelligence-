## Как передать данные нативному отчёту

Подготовь объект REPORT_DATA, где каждый подтверждённый уровень (`article` и `group`) содержит собственные метрики, темы, полные цитаты, вопросы и возможности. **Передай все проверенные подтверждения виджету сразу**, а не только первоначально видимые 3–5. При локальном взаимодействии не вызывай повторный анализ или сетевые источники и не открывай другие сообщения. Данные из отзывов всегда считаются недоверенным текстом: показывай текст без исполнения разметки/скриптов, не вставляй его в код. Не выдумывай ссылки. Технические идентификаторы для сверки не должны быть видимыми элементами карточек.

Базовый объект области:

```json
{
  "version": 1, "report_id": "", "product": {}, "scope": {}, "dates": {},
  "metrics": {}, "summary": "", "themes": [], "quotes": [],
  "questions": [], "opportunities": []
}
```

Общий объект двух областей:

```json
{
  "version": 1, "report_id": "", "product": {},
  "areas": {
    "article": {"product": {}, "scope": {}, "dates": {}, "metrics": {}, "summary": "", "themes": [], "quotes": [], "questions": [], "opportunities": []},
    "group":   {"product": {}, "scope": {}, "dates": {}, "metrics": {}, "summary": "", "themes": [], "quotes": [], "questions": [], "opportunities": []}
  }
}
```

Передавай только подтверждённые области; совпавшие не дублируй. `areas.article` — реальные отзывы исходного nmId, `areas.group` — соответствующая подтверждённая группа. У каждой области отдельный знаменатель, период, список тем и доказательств. `report_id` = стабильная привязка к run_id; если содержимое меняется, различай ревизии в manifest и корректно сбрасывай несовместимое локальное состояние. Массивы необязательных пустых сущностей могут быть `[]`; неизвестные числа — `null`, а не выдуманный ноль.

Содержательные поля имеют следующие типы: `product` (идентичность товара), `scope` (область/покрытие), `dates` (период и время формирования), `metrics` (фактические числа), `summary` (проверенные выводы), `themes` (темы), `quotes` (реестр всех подтверждений), `questions` (точные Q&A), `opportunities` (гипотезы/проверки). Для полной проверяемости храни REPORT_DATA в `analysis.json` с графом наблюдений, без отдельного файла отчёта.

## Товар, область и даты

| Поле | Тип | Содержание |
|---|---|---|
| `product.name` | строка | Читаемое название товара или исследуемой группы. При отсутствии — нейтральное «Исследование отзывов». Длинное название сворачивается до трёх строк и раскрывается кнопкой «Полное название», без потери исходного текста. |
| `product.id` | строка | Артикул/идентификатор; передавать строкой, чтобы не терять точность. Для машинной связи, не обязательно показывается. |
| `product.url` | строка | Проверенная ссылка на карточку; доступна в раскрытии области. |
| `product.marketplace` | строка | Название площадки. Отсутствие не подменяется Wildberries. |
| `scope.label` | строка | Короткое видимое описание: конкретный артикул, группа вариантов или выбранная область. |
| `scope.description` | строка | Состав группы, существенные различия, ограничения сопоставимости и охвата. |
| `scope.variant_count` | целое ≥ 0 или null | Подтверждённое число вариантов; показывается отдельной метрикой. |
| `scope.coverage` | объект | Поля `status` и `basis`. |
| `scope.coverage.status` | строка | `unknown`, `owner_confirmed` или `source_confirmed`. Без поля подтверждение не показывается. |
| `scope.coverage.basis` | строка | Основание, источник и дата подтверждения/ограничения. Не выводить полноту из совпадения одного счётчика. |
| `dates.start`, `dates.end` | строки | Границы периода отзывов. Рекомендуется ISO `YYYY-MM-DD`; выводятся как переданы, без изменения часового пояса. |
| `dates.generated_at` | строка | Время формирования снимка ISO 8601 с часовым поясом, показано в подписи. |

Не приписывайте название входной карточки всем вариантам группы. `report_id`, `product.id`, `review_id` и другие ID не должны содержать токены или персональные данные.

## Показатели

| Поле `metrics` | Значение |
|---|---|
| `returned` | Число уникальных фактически полученных записей. |
| `text` | Число записей с пригодными непустыми покупательскими text/pros/cons в выбранной области. Базовый знаменатель частот. |
| `empty` | Число записей без пригодного покупательского текста. |
| `analyzed` | Число фактически прочитанных и размеченных текстовых записей. |

Значения — неотрицательные целые либо `null`. Отсутствующее значение не показывается; переданный `0` показывается как ноль. Если все три показателя заданы, `text + empty ≤ returned`: неразобранный остаток (например, повреждённые поля) нужно явно описать в `scope.description` и не выдавать его за пустые отзывы. `analyzed ≤ text`. При известном меньшем `analyzed` статус явно показывает неполную обработку. Пустой корпус не означает отсутствие проблем или положительных качеств.

Передавать частоты до завершения обработки допустимо как явно промежуточный результат или при документированном реальном препятствии по 02-ANALYSIS.md; это не штатный итог. Обозначьте неполноту, точную причину, объём остатка и выбранный знаменатель в `scope.description`. По умолчанию доли считаются от `metrics.text`, а не от обработанной части. Не объединяйте знаменатели разных исследований. Нативный отчёт принимает как один набор данных (для обратной совместимости), так и две области `areas.article` / `areas.group` в одном отчёте. В последнем случае у каждой области строго собственные `metrics`, `scope`, `dates`, `themes`, `quotes`, `questions` и `opportunities`, а переключатель обновляет все показатели одновременно.

## Темы: элемент `themes`

| Поле | Тип | Правило |
|---|---|---|
| `id` | непустая строка | Уникально в массиве тем, стабильный ключ для связей. |
| `title` | непустая строка | Конкретная тема. Перефразы согласовать до формирования отчёта. |
| `context` | строка | `positive`, `negative` или `neutral`. Определяется смыслом, не именем поля pros/cons или звёздами. |
| `count` | целое ≥ 0 | Число уникальных review-ID с темой и этим контекстом. |
| `denominator` | целое ≥ 0 или null | Необязательно. При отсутствии/null берётся `metrics.text`; если и он неизвестен, доля `—`. При нуле доля не определена. |
| `quote_ids` | массив уникальных строк | ID из реестра `quotes`. Для полного отчёта включи минимум одно точное подтверждение для КАЖДОГО уникального review-ID, вошедшего в `count`. Если меньше, пометь набор как частичный. |
| `evidence_status` | `complete`/`partial` (обратно совместимое поле) | В новых отчётах 4.2 передавай явно. `complete` — множества review-ID разметки и проверенных подтверждений точно совпадают и имеют размер count; выдержки и full_field_text сверены с корпусом. `partial` — проверка или связи неполны; причина и доступная доля обязательны, интерфейс не обещает недостающие цитаты. |
| `important` | boolean | Необязательно. `true` включает тему в отдельное раскрытие важных сообщений. Это метка аналитика, не автоматически определённая опасность. |

Доля вычисляется как `100 × count / denominator`, округляется до двух знаков только для показа. `count ≤ denominator` при известном знаменателе. Процент отдельно не передаётся. Темы сортируются по count; в обзоре показываются три наиболее частые положительные и отрицательные темы. Все темы, включая нейтральные, остаются во вкладке «Темы». Доли разных тем могут пересекаться и не обязаны давать 100%.

Повтор одной темы в отзыве не добавляет голосов. Один mixed-отзыв может присутствовать в двух контекстах. Разные цитаты одного отзыва не означают разных покупателей. `count` не вычисляется по количеству фрагментов: в полном наборе `count` должен равняться количеству уникальных review-ID в связях данной темы. Публикуемые 3–5 выдержек — лишь первая порция интерфейса, не всё содержимое реестра. Проверку дедупликации и исходных полей выполняет этап подготовки данных, а не оформление.

## Отображение и внутреннее хранение полей цитаты

**Видимые метаданные — строго два: дата (`date`) и реальный артикул (`product_id`).** Показывай их сразу под цитатой (например, «11.10.2026 · Артикул WB 866286844»). Полный исходный текст соответствующего поля можно раскрыть внутри карточки, не меняя отображаемых метаданных. `review_id`, `field` (=`source_field`), ID цитаты и отладочные ссылки **никогда не показывай читателю**: ни под цитатой, ни по нажатию «Источник»; они нужны для аудита, дедупликации и сверки и должны остаться в JSON/Facts.

Кнопки раскрытия «Показать ещё»/«Показать все» работают локально в той же карточке, без нового сообщения. Кнопка «Источник цитаты» с review-ID/source_field недопустима. Число «k из n» относится к уникальным отзывам, а не к фрагментам цитат.

## Цитаты: элемент `quotes`

| Поле | Тип | Правило |
|---|---|---|
| `id` | непустая строка | Уникальный ключ выдержки. Несколько выдержек одного отзыва имеют разные id. |
| `review_id` | непустая строка | Оригинальный либо устойчивый локальный ID покупательской записи. **Только для хранения, сверки и связей, не для показа в UI.** |
| `text` | непустая строка | Дословная выдержка из своего покупательского поля, без пересказа, искусственного обрыва или непомеченного сокращения. |
| `full_field_text` | непустая строка; обязательна для полного подтверждения в новом отчёте 4.2 | Полный точный текст оригинального `text`, `pros` или `cons`, которому принадлежит выдержка, после документированной очистки персональных данных. Нужен для просмотра полного контекста. |
| `product_id` | строка | Фактический артикул отзыва; не заменять входной карточкой группы. |
| `date` | строка | Дата записи, желательно ISO 8601. |
| `field` | строка | Исходное покупательское поле: обычно `text`, `pros` или `cons`. **Только для хранения и проверки; скрыто в UI.** |
| `source_url` | строка | Проверенная HTTPS-ссылка на запись/источник. Если прямой ссылки нет, поле опустить; не выдумывать URL отзыва. |

Не включать имена, buyer-ID, контакты, медиа и токены. Редактирование чувствительных фрагментов должно быть выполнено до формирования REPORT_DATA и описано в ограничениях. Ответ продавца не становится покупательской цитатой. Виджет сначала показывает 3–5 подтверждений, затем раскрывает остальные локально в той же карточке; полный текст поля — во вложенном раскрытии. Использование нового сообщения через GenUI.issueNewTurn для «Показать ещё» запрещено. Отображайте «показано k из count», и если связей недостаточно — предупреждение о частичном наборе, а не ложную кнопку. Поиск работает по названиям тем и связанным точным выдержкам, без повторного AI.

## Вопросы и ответы: элемент `questions`

| Поле | Тип | Правило |
|---|---|---|
| `id` | непустая строка | Уникальный ID вопроса. |
| `question` | непустая строка | Текст вопроса. |
| `asked_at` | строка | Дата вопроса, необязательно. |
| `source_url` | строка | Проверенная ссылка на источник вопроса. |
| `answers` | массив | Может быть `[]`, в этом случае показано отсутствие ответа в переданных данных. |
| `answers[].text` | непустая строка | Текст ответа. |
| `answers[].role` | строка | `seller`, `buyer`, `platform`, `unknown`. Неизвестная роль отображается как неизвестная. |
| `answers[].date` | строка | Дата ответа, необязательно. |
| `answers[].source_url` | строка | Проверенная ссылка на источник ответа, необязательно. |

Вопросы/ответы не входят в `metrics.text`, `themes.count` и покупательские цитаты. Заявление продавца — позиция продавца, не проверенное свойство товара. При `questions: []` вкладка корректно сообщает «Вопросы и ответы не переданы», а не утверждает, что их нет на площадке.

## Возможности улучшения: элемент `opportunities`

| Поле | Тип | Правило |
|---|---|---|
| `id` | непустая строка | Уникальный ID возможности. |
| `title` | непустая строка | Конкретное предлагаемое действие. |
| `observation` | строка | Наблюдение из корпуса, отдельно от гипотезы. |

## Проверка контракта и встроенного интерфейса

До построения убедись, что все ID тем и цитат уникальны в своей области, ссылки `quote_ids` и `theme_ids` разрешаются, `count` целое и не превышает знаменатель, `metrics.text+metrics.empty ≤ metrics.returned` (если известны все), а `metrics.analyzed ≤ metrics.text`. Данные должны соответствовать реальному корпусу. Допустимость JSON не означает завершённости анализа.

Для каждой пары тема/context сравни **множество** review-ID наблюдений с множеством ID связанных проверенных цитат. Сверь точную подстроку, `full_field_text`, очищенное поле корпуса, даты и nmId. При неполном реестре помечай `evidence_status=partial` с доступными `k/n` и причиной. Все 3–5 первых цитат — только предел первоначального показа; полный список остаётся в виджете и `analysis.json`.

Прочитаны все text/pros/cons каждого уникального текстового отзыва: `metrics.analyzed=metrics.text` и `pending_IDs=[]` для завершённой области. При документированном препятствии оставляй полный список в `manifest.json`. Статусы полноты сбора, обработки, доказательств и UI независимы. UI должен содержать переключатель областей, четыре вкладки, три фильтра, поиск в скрытых цитатах, локальное раскрытие цитат и полных полей, работающие переходы от выводов и возможностей к темам. Проверенные и непроверенные действия разделяй; статусы UI записывай в manifest, не вводя ненужные новые поля контракта.

Хранение: `corpus.jsonl` (очищенные тексты и ID), `analysis.json` (весь граф, разметка, Q&A и REPORT_DATA), `manifest.json` (источники, метрики, обработка, факты и контрольные суммы). Не дублируй одни и те же большие массивы в нескольких артефактах без причины. HTML-файлы, fixtures и тестовые отзывы не являются результатами исследования.

## Контролируемый экспорт · 0.4.0

REPORT_DATA.version остаётся 1. Внутри analysis.review_status обязательны отметки полей и record/scope хеши; observations новых порций сохраняют source_field/excerpt. Сборщик экспортирует полные данные только после PASS обработки, доказательств и контракта. Дополнительный объект readiness в экспорте содержит input_sha256, source_complete, processing_complete, evidence_complete, ui_status, research_success, limitations; он не заменяет UI-проверку. Неполный источник требует явного --allow-partial-source, но необработанный корпус/неподтверждённая тема блокируют любой итоговый экспорт. Интерактивному механизму передать все поля без срезов.
