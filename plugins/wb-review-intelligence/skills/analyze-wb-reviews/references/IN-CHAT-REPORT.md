# Отчёт прямо в ответе · 1.2.1

Постоянное предпочтение владельца: достаточно ссылки WB или артикула. Не требовать фраз «сохрани данные», «режим local_project», «внутри текущего проекта», вызова имени навыка или дополнительной просьбы показать отчёт. Эти действия являются частью обычного анализа. Применять по смыслу: обсуждение ссылки без запроса анализа не превращать в новый сбор.

## Хранение выбирается автоматически

В установленной локальной сборке Codex всегда использовать фактическую папку открытого проекта и local_project.py. В аккаунтном плагине Codex Desktop/CLI с постоянным пользовательским проектом также по умолчанию local_project. Если в проекте уже есть wb-review-intelligence/config.json, переиспользовать его и прежнюю историю, не спрашивая режим/папку. В ChatGPT Work с временной управляемой средой использовать ранее выбранный облачный маршрут. Явное новое указание владельца имеет приоритет; наличие одной лишь файловой системы /workspace не доказывает постоянный VPS.

## Одно хранилище и прежняя история

Новый анализ использует только local_project.py/pipeline.py этого плагина. Не создавать параллельный run в outputs/skill-runs ради project-local render. Старое требование проекта вызвать другой renderer отменяется при выборе этого плагина основным. Legacy-исследования открываются по сохранённым ссылкам, без копирования или сбора. Setup читает list, а не создаёт пустые run_id. Внешняя публикация не является частью локального сохранения.

## Отображение и хранение независимы

Локальное сохранение не отменяет показ в сообщении. До финального ответа определить доступный штатный механизм inline HTML в текущем клиенте. При наличии навыка Visualize/visualize/work-visualize загрузить его текущую инструкцию и следовать формату, разрешённым путям и ограничениям ЭТОГО клиента. Не просить пользователя повторять запрос или отдельно включать отчёт, если механизм уже доступен. Не подменять inline блок боковой вкладкой браузера, скриншотом, Markdown-ссылкой, результатом теста DOM или сообщением «готово».

Сначала обработать весь доступный корпус и проверить evidence/report. Команда local_project.py checkpoint <run_id> --render сохраняет report.html и дополнительно пытается собрать message.html тем же закреплённым renderer. Возвращает message_html, inline_reference и inline_ui_status=PREPARED_NOT_VERIFIED. При согласованном частичном источнике добавить --allow-partial-source. Данные, темы и подтверждения не срезать ради размера.

message.html — производная для встроенного показа, не четвёртый файл состояния. Он находится рядом с report.html, вне data. Его можно пересобрать без WB. При ограничении размера inline_blocked не отменяет сохранение самостоятельного report.html. Не использовать старую message.html после изменения input_sha256; только путь из успешной сборки текущего результата.

Если клиент поддерживает content reference Visualize с path и его правила допускают возвращённый путь, включить inline_reference в ПЕРВЫЙ итоговый ответ как настоящий content reference. Не выводить его в кодовом блоке, не заменять Markdown-ссылкой. Если штатный навык требует другое место/метод регистрации файла, выполнить его по текущему контракту, сохранив полную локальную версию. Открытие MCP App — только поддерживаемый в этом клиенте альтернативный способ, и только без неразрешённой загрузки локальных данных во внешнее приложение.

## Ограничения клиента и честный fallback

Инструкция плагина и подготовленный HTML не включают поддержку визуализаций в клиенте. Согласно документации OpenAI https://learn.chatgpt.com/docs/visualizations (проверено 20.10.2026), поддержка зависит от поверхности, аккаунта и версии; Codex CLI и IDE не отображают Visualize. Не переносить это утверждение автоматически на конкретный Desktop: проверить доступные ему инструменты/навыки. Не обещать проверенную inline-интерактивность на чужом VPS/Desktop без фактической проверки там.

Если inline не поддерживается, всё равно показать содержательный отчёт непосредственно В ТЕКСТЕ ответа: товар и период, отдельные метрики article/group, ограничение охвата, выводы, все тематические частоты (включая единичные, если помещаются), проверенные цитаты, Q&A и рекомендации. При лимите ответа явно назвать непоказанный объём; сохранить все данные в HTML и JSON. Ссылка на HTML — дополнительный доступ. Не заканчивать одной ссылкой или инструкцией открыть файл. Кратко назвать ограничение интерфейса один раз, без предложения повторить анализ.

## Статусы

Успешная сборка или вставленный content reference означают подготовку/отправку, а не подтверждённое отображение. Не выставлять UI=PASS за один render или автоматический тест. Фактические взаимодействия проверяются в предназначенном клиенте; до этого оставить UI непроверенным. Это не повод остановить анализ или потерять локальную контрольную точку.
