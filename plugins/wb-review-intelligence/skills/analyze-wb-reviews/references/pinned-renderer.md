# Закреплённый renderer · переносимый пакет1.3.0

Исходники renderer1.0.0: assets/report/shell.html, report.css и report.js. Они включены в пакет, работают на переданных данных без приватного App и без загрузки отзывов из сети. Не переписывать дизайн или обработку тем в ходе исследования.

## Локальный проект

После PASS processing/evidence/report выполнить local_project.py --project <корень> checkpoint <run_id> --render. Для честного неполного источника добавить --allow-partial-source. Самостоятельный report.html и фрагмент message.html находятся рядом с data; это производные одного запуска, не четвёртый файл состояния. Возвращённый inline_reference включить в первый итоговый ответ по контракту фактического клиента.

## Другая среда исполнения

pipeline.py <папка> render --out <разрешённый абсолютный путь вне data>. При частичном источнике добавить --allow-partial-source. Выбирать доступное долговременное место по среде, не предполагать /workspace на любом компьютере. Использовать навык Visualize текущего клиента, если он доступен; поддержка встроенного HTML зависит от клиента. Ссылка или факт render не доказывает UI=PASS.

Передавай все темы, цитаты, полные поля и Q&A. Большой самостоятельный HTML не требует усечения данных; если inline превышает лимит или не поддерживается, сохранить полный файл и выдать содержательный Markdown с точным ограничением. Не вызывать несуществующий MCP-инструмент и не загружать данные в сервис автора.

Renderer должен использовать исходный REPORT_DATA, экранировать недоверенный текст, работать без нового AI/сбора, показывать четыре вкладки, фильтры, поиск и локальное раскрытие подтверждений. Проверить применимые элементы или оставить их not_verified. Нельзя выдавать DOM-тест за реальные действия пользователя. Смена оформления не меняет исходники/разметку; после изменения данных старый UI receipt недействителен.
