# Запуск исследования и получение данных

Версия комплекта RI-PROJECT-4.4.0 от 17.10.2026. Правила проекта Review Intelligence.

1. ЗАПУСК
Артикул/ссылка/список — сразу исследуй без повторения задания и подтверждения. Числовой артикул без площадки считай WB. Уточняй лишь препятствующую работе неоднозначность. По умолчанию обязательны «Вся группа» и «Исходный артикул» по подтверждённому product-ID (WB: nmId). У каждого свои объём/период/темы/n/N/цитаты/выводы. Покажи различия; артикул — подмножество группы, числа не складывай. Без привязки разделение неизвестно; совпавшие области не дублируй. Запрос «только артикул/группа» приоритетен. Обе области — один run_id/папка/реестр. Опыт группы не приписывай одной модели.

Проверь источники/реестр. Новый сбор — новый снимок; уточнения, сравнения и **исправления интерфейса/раскрытия цитат** — сохранённые данные с датой, без повторного скрейпинга. Не добавляй отдельный run_id ради исправления формы отчёта.

2. ИНСТРУМЕНТЫ И ПОЛУЧЕНИЕ ДАННЫХ
Используй два доступных подключения для чтения публичных источников: **Firecrawl (основной для WB) и Tavily (резервный)**; также веб/Python/файлы. Выбор означает порядок попыток, не обещание полноты. Проверяй подключение, кредиты, статус HTTP и содержимое. Python не гарантирует интернет. Не предполагай локальный доступ/ключи. Без установки расширений, серверов, БД. Если Firecrawl недоступен, пробуй Tavily на том же подтверждённом адресе. Если Firecrawl вернул неполный, но пригодный корпус, **не запускай Tavily автоматически ради добора**: оцени полученное покрытие, укажи его ограничения и продолжай исследование на фактически полученных данных, когда такой охват принимается владельцем. Tavily для добора включай при прямом запросе на максимальный охват, при недостатке данных для осмысленного анализа или при другой существенной необходимости. При объединении источников сравнивай исходные review-ID, а не длину ответа. Нельзя объявлять полную замену или полное покрытие без доказательств.

**WB, подтверждение карточки и группы:** nmId → https://cdn.wbbasket.ru/api/v3/upstreams → подтверждённый `origin`/диапазон для vol=nmId//100000 → `/vol<vol>/part<nmId//1000>/<nmId>/info/ru/card.json` на указанном сервере → проверка `nm_id`, `imt_id`, `colors`/`full_colors`, `supplier_id`, варианта модели и комплектации. nmId не заменяет ID группы. Для разных моделей в склейке сохраняй отдельные наименования; опыт группы не приписывай одной модели. Проверяй текущий ответ.

**Firecrawl Scrape (первый способ):** запрашивай только подтверждённые URL; для живой проверки `formats=["markdown"]`, `onlyMainContent=false`, `maxAge=0` (без устаревшего кэша). Не применяй генеративное `jsonOptions`, когда источник уже JSON. Сверяй HTTP 200, `contentType=application/json`, затем программно извлекай валидный JSON из возвращённого блока JSON (обычно ограждённого разметкой Markdown); никакого восстановления отсутствующих полей и текстов. Для отзывов проверь `https://feedbacks1.wb.ru/feedbacks/v2/<подтверждённый imt_id>` (возможные другие версии/зеркала только если документированы и проверены, не перебирай хосты). `feedbacks[]` — фактически полученный массив; `feedbackCount` и `feedbackCountWithText` — отдельные счётчики API, **не** длина корпуса. Проверь review-ID, реальные nmId, даты, точные `text`/`pros`/`cons`; дедуп по площадке/группе/review-ID, отдельно два объёма: исходный артикул и вся группа. Если `len(feedbacks) < feedbackCount` или реально полученные тексты меньше `feedbackCountWithText`, пометь охват как неполный; не заявляй «все отзывы» и не переноси прежнюю полноту на другой товар. При согласованном частичном охвате не блокируй отчёт: частоты `n/N` рассчитывай **по фактически полученным уникальным текстовым отзывам конкретной области**, отдельно приводи сопоставление с API-счётчиком и предупреждай о возможном смещении выборки. Не используй `feedbackCountWithText` как знаменатель тем при неполной выгрузке. Пример проверочного запуска WB 209956744 от 17.10.2026: группа 615 текстовых из 826 фактически полученных отзывов, API-счётчик текстовых 794 (сопоставимое покрытие 77,5%, не доказательство полноты); исходный артикул — 432 текстовых из 600 полученных. Эти числа относятся только к конкретному снимку и не являются универсальным порогом принятия.

**Постраничный API отзывов:** опубликована сторонняя реализация `POST https://feedbacks{1,2}.wb.ru/api/v1/feedbacks/site` c JSON `{imtId,skip,take,order}` и возможным `valuation`. Этот путь **не подтверждён рабочим в Firecrawl**: 17.10.2026 на двух серверах при реальном товаре получен `HTTP 200`, но `feedbacks:null` и нулевые счётчики. Не считать HTTP 200 успехом и не продолжать пагинацию из пустого «stub». Повторять только при появлении проверенного способа и без обхода защиты, перебора хостов и выдуманной пагинации. Результаты сторонних репозиториев — ориентир для теста, не доказательство результата.

**Публичные Q&A WB (Firecrawl):** проверенный маршрут `https://questions.wildberries.ru/api/v1/questions?imtId=<imt_id>&take=30&skip=<смещение>`; `take` не более 30, `skip` увеличивать на фактический размер страницы. Проверяй `count`, уникальные question-ID, `imtId`, фактический `nmId`, полный текст вопроса, дату и отдельно `answer.text`, `answer.createDate`, роль ответа продавца. Собирать страницы до исчерпания только при успешных ответах; `questions:null`, некорректная схема или пустой HTTP 200 не подтверждают отсутствия вопросов. В пользовательском отчёте не выводи имена, покупательские ID, метаданные профилей.

**Tavily Extract (резерв):** advanced, format=text, без query, если допустимо. Может использоваться для повторной проверки карточки/JSON, при отказе Firecrawl либо для дополнительных публичных источников. Сверяй IDs между источниками; не складывай пересекающиеся выгрузки. При исчерпанных кредитах не обещай доступ. Предпочитай валидный JSON первоисточника; повреждения не исправляй догадками. Поисковые обрывки не являются корпусом.

**Контроль стоимости и отказов:** до и после теста Firecrawl при наличии вызови `firecrawl_credit_usage`; обычный Scrape стоит 1 кредит/URL в испытанном тарифе, Interact и дополнительные форматы могут стоить больше; лимиты уточняй по текущим ответам/тарифу. Не делай повторных платных запросов ради перерисовки интерфейса — используй сохранённый корпус. Ограничивай таймауты и частоту; при 429 — один повтор с Retry-After. gzip допустим. При 403/498 или другом отказе не обходи защиту. Ozon проверяй отдельно. При недоступности полной выгрузки укажи неполноту, период и покрытие в обеих областях и продолжай на доступном корпусе, если это устраивает владельца; дополнительную выгрузку запрашивай лишь если она необходима для требуемой полноты или решения задачи.

3. ПОВТОРНЫЙ ПРОСМОТР
Доработка интерактивного представления, раскрытие ранее сохранённых подтверждений и скрытие технических полей — не новый сбор. Используй сохранённые отзывы/разметку, не перезапрашивай WB ради интерфейса.

## Повторное использование и стоимость

Загружай подтверждённый корпус один раз на независимый снимок. После сохранения `corpus.jsonl` дорабатывай анализ, раскрытие цитат, оформление и встроенный отчёт из `corpus.jsonl` и `analysis.json`, не обращаясь повторно к WB. Переиспользуй уже полученные карточку, Q&A и метаданные. Не сохраняй каждый ответ API, страницу пагинации или пробный формат отдельным итоговым файлом: источник, параметры, исходный объём, статусы и существенные ограничения зафиксируй в `manifest.json`. Если сырой ответ содержит уникальные необходимые данные, включи их в очищенный корпус или документированное вложение, а не теряй.

Сначала используй данные и методы сохранённого запуска; новые платные вызовы только если без них нельзя выполнить конкретную задачу либо владелец поручил новый сбор.

## Передача контролёру · 0.4.0

Каждую успешно полученную порцию сразу передавать `pipeline.py <папка> ingest --input -`; не держать весь прогресс только в контексте чата. Состав article/group и реальные исходные счётчики передавать через coverage по контракту `02-ANALYSIS.md`. Unknown/null и ограничение сохранять как есть. collection=BLOCKED при неполном источнике не означает необработанный корпус; продолжать его полную обработку. Ни согласие на частичный охват, ни равенство локальных чисел не превращают покрытие в PASS. Новый сбор для изменения отчёта не нужен.
