# Эталон встроенного интерактивного отчёта · RI-PROJECT-4.4.0

**Это иллюстрация к нормативному `ui-contract.md`.** Встроенный отчёт показывается в ТОМ ЖЕ сообщении ChatGPT; никаких HTML-файлов, отдельных страниц, ложных кликабельных элементов или новых обращений к модели при нажатии. Не использовать числа, цитаты и вопросы из примера как факты о реальном товаре. Плейсхолдеры в `{скобках}` заменяются исключительно проверенными данными.

## 1. Каркас на телефоне

```text
{Название товара}                       {период}
[Исходный артикул] [Вся группа]          ← не обрезать метки
[Получено {N}] [С текстом {N}] [Обработано {N}]
Охват: {известен или «не подтверждён»}
Статус: {ПОЛНЫЙ АНАЛИЗ / ЧАСТИЧНЫЙ: причина}

[Обзор] [Темы]
[Вопросы] [Возможности]                  ← разрешён перенос в 2 ряда

Вкладка «Темы»:
[Все] [Хвалят] [Критикуют]
[🔎 Поиск по темам, отзывам и цитатам]
Найдено {k} из {T} тем выбранной области

▸ {Название темы} · {тональность}
  {n}/{N_text} · {процент}% · {доступные цитаты: k/n}

После открытия ↑ в ЭТОЙ ЖЕ карточке:
▾ {Название темы} · {тональность}  {n}/{N_text} · {%}
  «{точная выдержка 1}»
  {дата} · WB {фактический nmId}
  [Полное поле ▾]                        ← раскрывает исходный текст поля
  «{точная выдержка 2}»
  {дата} · WB {фактический nmId}
  ... всего первая порция 3–5 подтверждений ...
  [Показать ещё] [Показать все]
  Показано {k} из {доступно} подтверждений
```

Все элементы — **функции**, а не имитация кнопок в тексте. На узком телефоне меню вкладок должно переноситься, прокручиваться с видимым индикатором либо заменяться компактным селектором; запрещены обрезанные «Исходный артик...» и «Возможнос...». Карточки и метрики не выходят за экран, цитаты переносятся, нет горизонтального скролла всего отчёта.

## 2. Обязательные состояния и действия

| Действие | Изменение в этом же сообщении | Проверка |
| --- | --- | --- |
| Исходный артикул → вся группа | Метрики, период, охват, `N_text`, проценты, темы, цитаты, вопросы, возможности и выводы меняются на данные группы. Обратное переключение возвращает артикул. | Ни одна частота и цитата другой области не подмешиваются. Группа не приписывается исходному артикулу. |
| Обзор → Темы | Показываются ВСЕ классифицированные темы, включая частоту 1. | Число доступных тем равно числу тем в данных выбранной области. |
| Темы → Все / Хвалят / Критикуют | Список ограничивается тональностью с учётом текущей области и поиска. | «Все» показывает положительные, отрицательные, смешанные/нейтральные темы; смешанные не исчезают из «Все». |
| Ввод текста в поиск | Моментально фильтруются доступные темы по названию, всем связанным точным цитатам, включая ещё не показанные, и полному тексту поля. Для вопросов — по формулировкам и ответам. | Скрытая 25-я цитата позволяет найти тему, хотя карточка закрыта. Нет отправки сообщения/сетевого запроса. |
| Открыть тему | Внутри этой карточки появляются первые `min(5, число доступных подтверждений)` дословных цитат, даты и фактические артикулы. | Одновременно в свернутой карточке видны `n/N_text`, `%`, тональность. |
| Показать ещё | Добавляет очередные до 5 подтверждений внутри уже открытой карточки. | Ничего не переносит на отдельную страницу, не меняет область и не открывает новый чат. |
| Показать все | Показывает все оставшиеся переданные подтверждения темы в этой же карточке. | После исчерпания кнопки скрыты/недоступны. |
| Полное поле | Раскрывает точный очищенный `full_field_text` данного источника цитаты. | Данные берутся из существующего корпуса, не генерация нового текста. |
| Обзор: открыть основную тему | Переводит на «Темы», раскрывает соответствующую карточку, сохраняя область. | Переход имеет реальный обработчик и показывает нужную тему. |
| Вопросы | Показывает фактически выгруженные Q&A, источник ответа и раскрытие, либо явное «данные Q&A не получены». | Не создаются «частые вопросы», которых нет в исходных Q&A. |
| Возможности | Каждая рекомендация содержит проблему/сигнал, гипотезу, действие, проверку и переход к подтверждающей теме. | Нет рекомендаций без источника. |

При изменении области старые выбранная тема, раскрытия и поисковый запрос не должны создавать визуальные противоречия; можно сбросить их до безопасного состояния. У всех кнопок должны быть обработчики. Если технологически действие невозможно, не изображай его работающим.

## 3. Контракт карточки темы

- Краткое название, тональность, частота `n/N_text` и процент рядом с заголовком **даже когда карточка закрыта**.
- `n` = число **уникальных** отзывов, которым сопоставлена данная тема/context. `N_text` = все текстовые уникальные отзывы области, включая прочитанные без тем. `% = 100*n/N_text`, не доля от количества цитат.
- Все темы из `analysis.json` включаются в виджет без ограничения Top-10/Top-20. Ни одна единичная тема не пропадает.
- Доказательства: каждому уникальному ID, вошедшему в `n`, соответствует хотя бы одно верифицированное подтверждение с точным фрагментом и полным исходным полем. Все подтверждения передаются при первом рендере, а не загружаются по запросу.
- Первоначально видны 3–5 подтверждений (при меньшем количестве — все). Режим `Показать ещё` добавляет по 5, `Показать все` показывает всё. Кнопки не должны зависеть от количества видимых примеров в исходном prompt.
- Под цитатой отображать **исключительно дату и реальный WB nmId**. Review-ID, source_field, внутренние идентификаторы и технические ссылки остаются за пределами UI, но присутствуют в `analysis.json` для аудита.
- Если подтверждений действительно `k<n`, писать `подтверждены k из n` с причиной; кнопки ограничены именно k реальными доказательствами. Не называть `k` частотой темы.

**Пример только структуры (не реальные отзывы/числа):**

```text
▾ {Недостаточная яркость} · Критикуют · {n}/{N_text} ({p}%)
 «{проверенная цитата из корпуса}»
 {2026-..-..} · WB {nmId}
 «{следующая проверенная цитата}»
 {2026-..-..} · WB {nmId}
 [Показать ещё {до 5}] [Показать все {оставшиеся}]
```

## 4. Статус отчёта: не смешивать ограничения

**Завершённый анализ** допустимо обозначать только когда по подтверждённой области `N_analyzed=N_text`, `pending_IDs=[]`, разметка всех тем (включая единичные) завершена, частоты и все связи с цитатами проверены. Неполнота выгрузки относительно API-счётчика — **отдельный** статус охвата источника, который отображается честно и не доказывает неполноту обработки реально полученного корпуса.

**Частичный анализ** допустим лишь при конкретном неустранённом препятствии. Покажи что именно не готово, реальный объём обработанного `N_analyzed/N_text` и источник ограничения. Не подменяй обязательную работу над доступным корпусом фразами «предварительная разметка», «показаны лишь примеры», «частоты не указаны». Нельзя сознательно оставлять доступные отзывы неразмеченными ради быстрого UI. Запрещено вычислять частоты по первым нескольким цитатам или выдавать 3 примера за 3 отзыва темы.

## 5. Проверка перед ответом (приёмка)

- [ ] Встроенный, а не HTML, не изображение и не внешний сайт; нет неподтверждённых обещаний интерактивности.
- [ ] Обе реальные области переключаются со всеми зависимыми данными; неизвестные области не имитируются.
- [ ] Есть все 4 содержательные вкладки и 3 фильтра; мобильные подписи читаются полностью.
- [ ] Все темы, в том числе единичные, доступны; каждая имеет `n/N_text` и `%`.
- [ ] Все подтверждения переданы на вход интерфейсу; никакой срез из «первых примеров» не подменяет корпус.
- [ ] При раскрытии видны первые 3–5; `Показать ещё` и `Показать все` меняют только эту карточку.
- [ ] Поиск находит темы по скрытым цитатам и полным полям, сочетается с выбранной областью и тональностью.
- [ ] Цитаты дословны и под ними только дата + WB nmId; полный текст поля раскрывается локально.
- [ ] Вопросы и возможности содержат проверяемые данные и рабочие переходы.
- [ ] Статусы охвата, смыслового анализа, подтверждений и UI разделены; непроверенные клики отмечены как непроверенные.

Оформление закреплено в `assets/report/` и не генерируется заново. Достоверность, полнота, видимость частот, содержание вкладок, локальная работа действий и мобильная читаемость обязательны.
