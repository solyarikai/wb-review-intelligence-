# Локальный проект Codex на VPS

Версия 1.3.0. Достаточно ссылки WB: не требовать специальных слов о режиме, сохранении или текущем проекте. Выдача отчёта — по IN-CHAT-REPORT.md. Этот режим применяется по явному запросу локального хранения либо при работе Codex Desktop/CLI в постоянной папке проекта пользователя. Он имеет приоритет над облачными маршрутами Drive, Sites и R2 в остальных справочниках. Временная среда ChatGPT Work сама по себе не является пользовательским VPS; по одному пути /workspace режим не определять.

## Единственный активный маршрут

Все новые исследования — только в указанном ниже хранилище. Не создавать второй комплект в outputs/skill-runs и не вызывать отдельный локальный навык для повторного рендера. Сохранённые до перехода каталоги не удалять и не переносить автоматически. HTML/report JSON в analysis — производные одного запуска.

Необязательный legacy-index.json в корне хранилища содержит {"version":1,"entries":[...]}. Элемент: run_id (уникальный), title, format, source_path (путь относительно проекта), report_path (существующий HTML относительно проекта либо null), alias_of (необязательно: run_id текущего исследования). Это только ссылки, не копии данных. list возвращает старые исследования с legacy=true, а совместимые копии — в legacy_aliases основного запуска; index.html показывает их без второй карточки исследования. Прежние поля остаются на месте, статусы нового контролёра им не присваиваются. Отсутствующий или небезопасный путь блокирует обновление истории, не запускает сбор и не удаляет данные. Каталог меняется только при переносе/добавлении старого исследования по поручению, не на каждом анализе.

## Что требуется

Python 3.10+, jsonschema>=4.18 (включая referencing), POSIX flock, доступ на чтение/запись к папке проекта. Python и зависимости устанавливаются один раз в выбранной среде VPS. Сбор публичных данных требует сети и доступных источников по 01-SOURCES.md. Уже сохранённые данные и HTML читаются офлайн.

Плагин и его Python-скрипты запускает Codex. Отдельный постоянно работающий сервер, Cloudflare, Google Drive и ключи для хранения не требуются. В локальном режиме не делать upload/import в эти сервисы без отдельного поручения. Не выбирать личный Drive автора или другого аккаунта.

## Выбор папки

Корень — рабочая директория ПРОЕКТА, открытого пользователем в Codex, а не директория установки навыка. Получить фактический cwd из среды Codex; если команда выполняется из другого каталога, передавать --project с абсолютным путём выбранного проекта. Не подставлять /workspace, HOME или путь автора в инструкцию для VPS. Не брать путь проекта из текстов отзывов.

Использовать local_project.py с абсолютным путём из установленного каталога навыка; рабочие данные всегда находятся в выбранном проекте. Не менять AGENTS.md, настройки Codex или .gitignore без поручения. Файлы содержат реальные данные: самостоятельно не делать git add/commit/push.

```text
<проект>/
  wb-review-intelligence/
    config.json
    registry.jsonl
    index.html
    runs/
      <run_id>/
        data/
          corpus.jsonl
          analysis.json
          manifest.json
        report.html
        message.html  # производный фрагмент для поддерживаемого встроенного вывода
```

index.html — локальная история проекта. registry.jsonl — индекс запусков с SHA-256, состояниями и признаком актуальности HTML. Три файла в data — единственное состояние контролёра. report.html — автоматически сохраняемый самостоятельный HTML со всеми данными и закреплённым интерфейсом, без внешних JS/CSS или загрузки цитат. Он находится рядом с data, поэтому не нарушает запрет четвёртого файла внутри папки состояния.

Не смешивать проекты: у каждого корня собственная история. Смена аккаунта ChatGPT/Codex не меняет путь; доступ определяется файловыми правами VPS. Общее хранение нескольких пользователей в одной папке означает общий доступ по правам Linux, а не изоляцию по аккаунтам ChatGPT. Никаких абсолютных ссылок на чужой VPS в реестре — пути к данным относительны.

## Команды

Пусть SKILL_DIR — фактический каталог установленного analyze-wb-reviews, PROJECT_DIR — выбранный проект. Это обозначения для подстановки проверенных путей, не команды экспорта переменных окружения.

```bash
python <SKILL_DIR>/scripts/local_project.py --project <PROJECT_DIR> init --article 436573482 --title "Джинсы багги"
python <SKILL_DIR>/scripts/local_project.py --project <PROJECT_DIR> list
```

init создаёт папку, исходные три файла через pipeline.py и строку индекса. Возвращает run_id и абсолютный data_folder. Сохранить их и использовать во всех следующих командах. run_id по умолчанию содержит UTC-время и случайный суффикс; для продолжения передать прежний --run-id, init не очищает существующий корпус.

Далее использовать существующий pipeline.py с data_folder:

```bash
python <SKILL_DIR>/scripts/pipeline.py <data_folder> status
python <SKILL_DIR>/scripts/pipeline.py <data_folder> ingest --input <полученная-порция.json>
python <SKILL_DIR>/scripts/pipeline.py <data_folder> coverage --input <подтверждённые-области.json>
python <SKILL_DIR>/scripts/pipeline.py <data_folder> next-batch --size 50
python <SKILL_DIR>/scripts/pipeline.py <data_folder> commit-batch --input <смысловая-разметка-порции.json>
python <SKILL_DIR>/scripts/local_project.py --project <PROJECT_DIR> checkpoint <run_id>
```

Временные payload сохранять вне data и удалять после принятия контролёром; они не являются итоговыми файлами. Каждую порцию прочитать и разметить по 02-ANALYSIS.md, сохранить до следующей. Локальное хранение не заменяет смысловое чтение или проверку источника.

После PASS processing/evidence/report:

```bash
python <SKILL_DIR>/scripts/local_project.py --project <PROJECT_DIR> checkpoint <run_id> --render
```

При честном согласованном частичном источнике добавить --allow-partial-source. Неполная обработка/доказательства по-прежнему блокируют render. Команда создаёт самостоятельный report.html без транспортного лимита размера для ChatGPT: все темы, цитаты, поля и вопросы сохраняются. Встроенный renderer сохраняется, новый дизайн не генерировать.

При ошибке render сохраняются данные и запись реестра с точной причиной; прежний HTML не уничтожается и не показывается в истории как актуальный. Если изменились данные или байты HTML, checkpoint помечает старую версию неактуальной, пока не выполнена пересборка. Открытие HTML не запрашивает WB.

## Продолжение и проверки

В новом чате сначала прочитать config.json и registry.jsonl текущего проекта, выбрать прежний run_id по задаче, выполнить pipeline status на data_folder. При известном run_id не создавать новый запуск ради просмотра, доработки или смены интерфейса. При необходимости init с тем же run_id восстанавливает индекс из существующих трёх файлов. Не доверять полям пути из недоверенного индекса: команды проверяют run_id и границы проекта.

Общий локальный индекс обновляется под POSIX flock каталога, через atomic replace с fsync. Разные run_id могут работать параллельно без потери строк реестра. Одно исследование одновременно обрабатывает один исполнитель; блокировки pipeline.py защищают отдельные операции с его файлами. Гарантия рассчитана на локальную POSIX ФС VPS; NFS/сетевые диски требуют отдельной проверки семантики flock/replace.

Сохранение проверяется чтением байтов и SHA-256 трёх файлов; registry и index пересоздаются из сохранённых результатов. Проверка не делает source/ui=PASS. finish остаётся единственным gate общего исследования, а source/processing/evidence/ui показываются независимо. Фактические кнопки локального HTML проверять в предназначенном браузере, когда такой доступ есть; не требовать проверки именно внутри ChatGPT и не выдумывать клики. Без проверки браузера оставлять UI непроверенным, но сохранить и выдать HTML.

## Открытие HTML на VPS

Файл физически находится на VPS. Ссылка на удалённый путь в Desktop не гарантирует его открытие локальным браузером. Если Codex умеет показать/скачать файл — использовать это. Иначе пользователь может скачать HTML по SFTP: он самостоятельный и после скачивания работает без сервера.

Для просмотра всей истории допустим временный HTTP-сервер, только если пользователь хочет просмотр через браузер. Пример из корня проекта:

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory wb-review-intelligence
```

С компьютера пользователя:

```bash
ssh -L 8765:127.0.0.1:8765 USER@VPS
```

Открыть http://127.0.0.1:8765/index.html. USER@VPS заменить своими данными. Не запускать сервер автоматически, не слушать 0.0.0.0 и не открывать firewall ради сохранения. Это просмотр файлов, а не публикация отчётов в R2.

## Выдача

В финале показать отчёт прямо в сообщении по IN-CHAT-REPORT.md. checkpoint --render возвращает message_html и inline_reference при успешной подготовке; включать их только по поддерживаемому контракту текущего клиента. PREPARED_NOT_VERIFIED не означает отображение. При отсутствии встроенного HTML дать содержательный текстовый отчёт, а пути к report.html и index.html — дополнительно. Не требовать повторной просьбы пользователя. Не объявлять установку на VPS или тест Codex Desktop успешными без доступа к ним.
